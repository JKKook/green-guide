### 3-1. 음식물 vs 종량제 헷갈리는 것 (`food_inedible`, 11-03 사용자 추가)
기준: **동물이 먹을 수 없거나 딱딱해서 사료·퇴비가 안 되는 것은 종량제.**

| 종량제(`food_inedible`) | 음식물(`food_waste`) — 헷갈리지만 음식물 |
|---|---|
| 조개·굴·소라·전복 껍데기 | 수박·바나나·귤 껍질(부드러운 과일 껍질) |
| 게·가재·랍스터 등 딱딱한 갑각류 껍데기 | 새우 껍질(지역 따라 다름 — 안내에 "지자체 확인") |
| 닭뼈·돼지뼈·소뼈·생선 가시(큰 뼈) | 생선 살·내장 |
| 복숭아·자두·망고·감 씨 등 딱딱한 씨 | 사과·배 씨(작은 씨, 과육과 함께) |
| 달걀·메추리알 껍데기 | 삶은 달걀(내용물) |
| 호두·밤·땅콩 등 견과류 껍데기 | 밥·면·반찬 |
| 양파·마늘·옥수수 겉껍질, 옥수수대, 파 뿌리 | 채소 잎·자투리 |
| 티백, 한약재 찌꺼기 | 커피 찌꺼기(지역 따라 다름 — 안내에 "지자체 확인") |
| 고추씨·고춧대, 왕겨 | 과일 과육 |

- 지역마다 기준이 다른 항목(새우 껍질·커피 찌꺼기 등)은 결론 대신 "지자체 기준 확인" 안내를 붙인다.
- 학습 데이터: 원본 라벨에 없음 → 로컬 VLM 의사라벨 + 표본 검수. 서빙 단계에서는 VLM 재질의·규칙표로 먼저 처리한다.

## 4. 반영 순서 (사용자 11-03: 서빙 끝나면 바로 CNN)

1. 평가셋 eval_v2 — 97장 전부 새 축(재질·세부·상태·마크 보임) 사용자 확인 → 동결(sha256). holdout 18 은 라벨만 붙이고 채점은 최종 1회.
2. 서빙 — VLM 프롬프트 v3(재질+세부+상태 출력), 규칙표, 앱·서버 표시명·안내(`waste_info.dart`, `waste_classes` 시드, `streams.py`) 갱신 → eval_v2 gate 로 측정.
3. 학습 데이터 재라벨 — 원본 복원(aihub385 `_01`→dirty, TACO·OpenImages 원 카테고리 재크롭 → metal_can/scrap·broken) + qwen 로컬 VLM 의사라벨(밤 하루) + 사람 표본 검수.
4. CNN 재학습 — 기존 계층 헤드 + 상태 헤드. 2단계가 끝나면 바로 이어서 시작.
   - 1회차 결과(11-04): **미채택**(결정 33). 과신 때문에 gate 서빙이 37/65로 떨어졌다. 상태 축은 서빙에서 VLM이 맡고, 온도 보정(T 1.5)도 41/65로 미달이라, CNN 상태 헤드는 다음 재학습 회차에서 다시 본다.

## 5. 학습 라벨 판정 (11-03 리더)

## 6. 열린 항목
- **대형폐기물 경로(보류, 11-03 사용자)**: 배출 축에 bulky 는 있으나 규칙표에 도달 경로가 없다(예: 기타 하드케이스·가구·큰 장난감 → 지금은 종량제로 안내됨). VLM 2단에 '대형 여부' 질의 + 대형이면 bulky 규칙을 넣는 안은 CNN v2 성능 개선 뒤 반영. eval_v2(골든셋 2차) 채점은 현재 기준으로만 한다.
- 상태 헤드 게이트 기준(정확도·오염 재현율)은 리더·팀원이 eval_v2 기준선을 보고 정한다.
- 판유리·거울의 재질을 `etc` 로 둘지 `glass` + composite 로 둘지는 eval_v2 라벨링 중 사례를 보고 확정.
