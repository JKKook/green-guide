# 시맨틱 융합 설계 — "VLM처럼 판단하기" (텍스트 × 정체 × 맥락)

> 2026-07-15 수립. 배경: 실사용 오답의 상당수는 CNN이 텍스처·형태 통계만 보기 때문.
> VLM(클로드류)이 약통/화장품을 구분하는 세 능력을 그린가이드 파이프라인에 이식한다.
> 지시: "CAM의 재질 + 이미지의 텍스트 분석 + 분리배출 표시 마크 인식을 통합"

## 0. 세 신호와 담당 컴포넌트

| VLM의 능력 | 그린가이드 구현 | Phase |
|---|---|---|
| ① 글자를 읽는다 | RapidOCR(PP-OCRv5 korean, onnxruntime) → 2계층 어휘 매칭 | **1 (즉시)** |
| ② 물체 정체를 안다 | CLIP 제로샷: 이미지 인코더 온서버 + 컨셉 텍스트 임베딩 사전계산 | 2 |
| ③ 장면 맥락을 본다 | 전체 프레임 증거(OCR·CLIP)를 각 물건 crop에 귀속/약한 prior | 2 |

기존 재질 신호(hier CNN + DINOv2 앙상블 + CAM 영역)는 그대로 — 위 신호들은
**fine 확률에 곱해지는 prior** 로 융합된다 (아래 §3).

## 1. 신호① 텍스트 — OCR 증거 (Phase 1)

- 엔진: `rapidocr` v3 (onnxruntime 전용, torch 불요) + PP-OCRv5 mobile korean.
  실측: 사진당 0.2~1.1s CPU, "현금승인번호" 0.99 / "CORELL" 0.94 / "BenQ" 0.90.
- 요청당 **원본(EXIF 정규화) 이미지에서 1회** 실행 → 텍스트 bbox를 물건 bbox/탭
  crop에 겹침 기준으로 귀속 (crop마다 재실행 금지 — 비용).

### 어휘 2계층 (src/semantic_evidence.py)

- **A급 = 분리배출 표시/재질어** (사실상 정답지 — 한국 포장재에 인쇄됨):
  무색페트/페트/PET → pet, HDPE/LDPE/PP/PS/OTHER/플라스틱 → plastic 계열,
  비닐 → vinyl, 캔/알루미늄 → can, 유리 → glass 계열, 종이팩/멸균팩 → carton,
  종이 → paper, 스티로폼/발포 → styrofoam, 일반쓰레기 → trash. 강도 strong.
- **B급 = 정체어** (물체 정체→재질 추론, VLM식):
  정/캡슐/유산균/약국/mg → 약통(plastic_other), 샴푸/로션/토너/에센스 → 화장품(plastic),
  소주/맥주/참이슬/카스/테라 → glass_deposit, 우유/두유 → carton,
  영수증/승인번호/사업자등록 → paper_other, BenQ/모니터/Galaxy → electronics 등. 강도 medium.
- 매칭: 공백 제거+소문자 정규화 후 부분문자열. OCR 오인식 대비 2글자 이상 토큰만.

## 2. 신호② 정체 + 신호③ 맥락 (Phase 2)

- CLIP **이미지 인코더만 ONNX 서빙**. 텍스트 인코더는 서빙에 불필요:
  컨셉 프롬프트("알약 통", "화장품 펌프 병", "소주병", "택배 상자"...) ~50개를
  오프라인에서 인코딩 → `clip_concepts.npz` (컨셉 임베딩 + 컨셉→fine 매핑).
- 서빙: crop 임베딩 × 컨셉 행렬 cosine → 정체 분포 → fine prior.
- 맥락: (a) 전체 프레임의 정체 분포를 각 crop prior에 약하게(0.2) 혼합 —
  "책상 위 전자기기들 사이" 같은 장면 정보. (b) OCR 증거의 공간 귀속(§1)도 맥락 처리.

## 2-1. 신호④ CAM 재질 융합 (Phase 2 — 탭 경로 우선)

사용자 결정(2026-07-15): CAM 재질 분석을 별도 경로로 두지 않고 탑라인에 융합한다.
**특히 탭 재분류는 사용자가 특정 영역을 지목하는 행위이므로, 그 영역의 CAM
재질 증거가 무조건 함께 고려되어야 한다.**

- 탭 경로(/predict-hier + tap): 전체 프레임 448² hi-res CAM(14×14) → 탭 성분
  bbox 내부의 클래스별 평균 활성 → 재질 분포 → fine prior (약한 가중 w_cam).
  crop 재분류(주 신호)와 CAM 영역 증거(보조)가 곱으로 결합.
- 일반 경로: CAM 은 같은 CNN 의 파생 신호(독립 증거 아님)라 이득이 제한적 —
  탭 경로 검증 후 확대 여부 판단.
- 주의: CAM prior 는 반드시 crop 분류보다 약하게 (w_cam ≤ 0.5) — 같은 모델의
  자기강화(오답을 CAM 이 재확인) 위험이 있으므로 보정 역할에 한정.

## 3. 융합 수식 (log-linear)

```
log p_fused(fine) = log p_ensemble(fine)            # CNN+DINOv2 (기존)
                  + Σ_e w_e · log prior_e(fine)      # 증거별 prior
→ renormalize
```
- prior_e: 매칭된 클래스에 boost_e, 나머지 1.0 (guidance 형제엔 √boost — 과잉확신 방지).
- 가중치 초기값: 마크 A급 w=1.0·boost 6, 정체어 B급 w=1.0·boost 2.5, CLIP 0.5, 장면 0.2.
  실사용 51장 + frozen 홀드아웃으로 튜닝. **원칙: 증거 없으면 기존과 완전 동일.**
- 게이트 상호작용: 융합은 게이트 **이전** 확률에 적용 → 강한 텍스트 증거가 있으면
  자연히 reject 가 풀린다 (별도 override 없음 — 단일 경로 유지).

## 4. API/앱 표면

- `PredictionHierResponse.evidence`: `[{type: mark|text, token, mapped_class, score}]`
- 앱 결과 카드에 "🔎 라벨에서 '무색페트' 인식" 신뢰 배지 (Phase 3).
- 적용 경로: /predict-hier(전체·탭), /predict-objects(후보별 귀속).

## 5. 성능 예산·배포

- OCR 0.2~1.1s(로컬 CPU) — HF Spaces에서 1~2s 예상. 정확도 최우선 지시에 따라
  기본 활성, env `WASTE_API_OCR=0` 으로 끌 수 있게.
- 모델 번들: det+rec+dict ~15MB를 `models/ocr/` LFS 로 고정 (런타임 다운로드 금지).
- 실패 격리: OCR 예외 시 증거 없음으로 진행 (기존 동작 보존).

## 6. 검증 계획

1. 실사용 51장: 융합 전/후 대분류·세부 정확도 (최소 비열화, 텍스트 있는 사진 개선 기대)
2. frozen test 샘플로 비열화 확인 (스튜디오 크롭엔 텍스트 적음 — 변화 ≈ 0 이 정상)
3. 신규 실기기 사진(약통·화장품·소주병)으로 A/B 케이스 확인

## Phase 2 실측 결론 (2026-07-15)

- 자산: build_clip_concepts.py — ViT-B/32, 66컨셉(정체→fine 매핑), 템플릿 앙상블,
  이미지 인코더 ONNX INT8 84MB (fp32 대비 cos ≥0.94, 순위 보존).
- **CLIP prior 는 경로를 가린다** (실사용 51장):
  - 장면(풀프레임): 39→36~38 로 **역효과** — 혼재 장면 center-crop 정체 오인
    (예: 검은 플라스틱 기기를 'a computer mouse' 0.99). 미적용.
  - 고립 crop(탭 대리): **25→29 (+4, w=0.5)** — 적용 (탭 + predict-objects 후보).
- 초기 prior 설계 결함 교정: '매핑됐지만 조용한 클래스 벌점'이 -3건 →
  **부스트 전용 + 확신 임계 0.30 + 우도비 상한 8** 로 재설계.
- **CAM 융합(신호④)**: 단독 0, w0.4+ 에서 -1~-4 (같은 CNN 자기강화 실증).
  사용자 설계 결정(탭 경로 필수 고려)에 따라 **w=0.15(무해 실측)** 로 탭 경로에
  융합, env WASTE_API_CAM_W 로 조정 가능. v7(회전증강) 이후 재스윕 권장.

## Phase 1 결과 + 도중 발견한 2개의 더 큰 레버 (2026-07-15)

Phase 1 평가 과정에서 **서빙 파이프라인의 구조적 회귀 2건**을 발견·수정 — OCR 자체보다
이쪽 효과가 훨씬 컸다. 실사용 51장, /predict-hier API 경로 기준:

| 구성 | 엄격 | 의미채점* |
|---|---|---|
| 수정 전 (EXIF세움 + u2크롭 + 솔로측정과 괴리) | 23/51 45.1% | 28/51 54.9% |
| + 회전 TTA(0/90/270 최대확신) | — | — |
| + 장면 분류 풀프레임 전환 (u2크롭 제거) | — | — |
| **최종 (TTA+풀프레임+OCR융합)** | **37/51 72.5%** | **42/51 82.4%** |

*의미채점: 게이트의 non_object 판정 ↔ truth 'etc'(분류불가) 를 동일 안내로 인정.

1. **방향 분포 어긋남**: AI-Hub 학습 크롭은 라벨 좌표(센서 방향, EXIF 미적용)로
   잘려 있어 모델이 '눕힌' 객체를 학습함. 서빙의 EXIF 세움이 입력을 분포 밖으로
   보냄 (세움 26 vs 눕힘 36/51). → 회전 TTA 로 서빙에서 흡수 (37/51). 근본 해결은
   **v7 회전 증강 재학습** (백로그).
2. **u2 자동크롭 역효과**: v2 시절 +2pp 근거가 v6+TTA 에선 역전 (TTA+풀 39 vs
   TTA+크롭 25). 장면 분류는 풀프레임, 탭 크롭만 유지.
3. OCR 융합: 이 51장에선 플립 0건 (텍스트 사진 5장뿐, 대부분 이미 정답) —
   확신 보정은 실측됨 (038 약국영수증 paper 0.45→0.82, 운영 0.69→0.89).
   가치는 라벨 있는 소비재(약통·화장품·병)에서 나타날 것 — 피드백 축적으로 검증.
