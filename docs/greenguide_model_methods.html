1. 시스템 개요

그린가이드는 사진 한 장으로 폐기물의 재질을 분류하고 거주 지자체 조례 기준의 배출 방법을 안내하는 시스템으로, 클라우드 경로(FastAPI 서버, 전체 파이프라인)와 온디바이스 경로(Flutter 앱 내 ONNX 단일 패스)의 이원 구조를 갖는다. 두 경로는 동일한 분류기 가중치를 공유하며, 차이는 추론 파이프라인(TTA·시맨틱 융합·VLM 중재 유무)에 있다. 설계 우선순위는 ① 분류 정확도 ② 반환 속도이다.

3. 전처리·정규화

  • 입력 정규화: RGB → 224×224 스트레치 리사이즈(bilinear, 크롭 없음) → [0,1] 스케일 → ImageNet 통계 정규화 mean=(0.485, 0.456, 0.406), std=(0.229, 0.224, 0.225). 학습(Python)과 온디바이스(Dart) 구현이 동일 수치를 사용한다.
  • 고해상 CAM: 재질 영역 분석은 448×448 forward → 25클래스 × 14×14 CAM (셀당 16px).
  • EXIF 방향: 학습 데이터(AI-Hub 크롭)는 센서 방향, 서빙 입력은 뷰어 방향 — 분포 불일치가 실측 정확도를 크게 훼손(26→36/51)하여 서빙에서 회전 TTA로 흡수한다(§5).
  • 저장용 재압축(수집 정책): EXIF 보정 + 긴 변 720px JPEG q80 — 장당 255KB→29KB 실측.

4. 학습 방법

  • 데이터: AI-Hub 생활폐기물(71385) 계층 크롭 + TACO 실외 실사 + 사용자 피드백. Kaggle류 스튜디오 이미지는 노이즈 부재로 기각.
  • 계층 구조: 대분류 14 / 세부 25 (taxonomy.json 사이드카가 정본 — fine→coarse 매핑·게이트·라벨 순서를 모델과 함께 배포).
  • 손실: fine CE + rollup loss(fine 확률 합산 → coarse CE) — 세부가 불확실해도 대분류가 견고하도록.
  • 증강: 표준 augment + ROT90(EXIF 방향 격차 완화).
  • 신뢰도 게이트 (표시 깊이 결정): fine 확신 ≥ 0.60 그리고 마진 ≥ 0.15 → 세부 표시; coarse ≥ 0.55 → 대분류 표시; 미달 시 reject(기타). OOD prototype 거리 τ_soft 0.30(세부 억제) / τ_hard 0.40(완전 reject — 탭 경로에서는 완화).
  • 평가 무결성: 피드백 사진(user_*)은 학습에서 영구 제외 — 과거 31/51 오염으로 실측 지표가 부풀려졌던 사고 이후의 원칙. 게이트 승격/롤백은 support ≥ 50 클래스의 recall 저하만 거부권을 갖는다(etc↔trash 동치 처리).
  • 지표 (hier_v2): frozen test coarse 96.4% / fine 93.2%, val coarse 94.3% / fine 90.2% (best epoch 9). 실사용(순수 홀드아웃)은 이보다 낮다 — §7.

5. 클라우드 추론 파이프라인과 최적화

운영 장면 경로 지연을 15s → 1.6s(9.4×)로 줄인 트랙과 정확도 융합 트랙의 조합이다. 순서대로:

단계내용최적화·근거
1. Stage1 게이트폐기물 여부 판정비폐기물 조기 종료, non_object 마스킹
2. 회전 TTAEXIF 태그 기반 후보 회전만 추론, 최고 확신 채택 B2: 태그별 축소 — 6→(0°,90°), 8→(0°,270°), 3→(0°,180°), 무태그 3방향. 3×→평균 1.7×
3. 조건부 OCR텍스트·마크 인식 → 어휘 부스트 (A급 마크 ×6, B급 정체어 ×2.5) B1: 1차 확신 ≥ 0.75면 스킵 (운영 −2~4s). 탭 경로는 항상 수행
4. CLIP·CAM prior정체 인식 prior(부스트 전용, 비율 상한 8) + 탭 영역 CAM prior(w=0.15) 탭(고립 크롭) 전용 — 장면 적용은 실측 역효과
5. 융합 재예측prior 를 로그-선형 곱 후 베스트 회전 텐서 1장만 재예측 TTA 전체 재실행 대비 1회로 절감
6. VLM 중재reject·coarse<0.55·증거-불일치(강한 CLIP 증거가 다른 대분류 지시) 시 Claude Haiku 최종 판정 재질 교체는 확신 ≥ 0.8, non_object 는 ≥ 0.5 (과신 가드). 일 200회 상한, 실패 시 무시(fail-open)
  • 기각된 최적화: INT8 양자화(주 모델) — QUInt8/per-channel에서 정확도 −1~−5pp라 채택 안 함 (CLIP 인코더만 INT8). u2netp 자동 크롭(장면 경로) — v6+TTA 하에서 역효과(39→25)라 전체 프레임 사용.
  • 탭-투-셀렉트 경로: GrabCut(탭 중심 창, ≤480px)으로 물건 실루엣을 픽셀 수준 분리 → 분류 크롭·빗금 영역 모두 실루엣 기반. 탭 = "물체 존재" 신호이므로 OOD 하드 reject 를 소프트(대분류 표시)로 완화. 크롭 최소 변 35% 보장(파편 크롭 방지).

6. 온디바이스 파이프라인

  • OTA 전달: 번들 모델 제거(앱 204→88MB, Play 200MB 한도 대응). 앱이 /model/latest → HF Hub(ethanDev92/waste-models)에서 ONNX + taxonomy 사이드카를 받아 캐시. sha256 검증, 실패 시 구캐시 → 클라우드 폴백.
  • 추론: 단일 패스 (TTA·융합·VLM 없음, non_object 마스킹 없음) → fine 확률 → 게이트 롤업 — 서버 /predict-hier 와 동일한 의미의 표시 수준(fine/coarse/reject)을 재현.
  • 폴백 정책: 온디바이스 저확신 시 클라우드에 재판정 위임(오프라인이면 로컬 결과 유지). 기본 모드는 클라우드.

7. 온디바이스 vs 클라우드 — 실측 비교 (2026-08-06)

피드백 라벨이 확정된 실사용 사진 51장을 동일 가중치·양 경로로 평가. 대분류(coarse) 기준 채점. hier_v2 학습에 포함됐던 33장(낙관 편향)과 학습에 없던 정직 서브셋 18장을 분리 집계.

세트온디바이스클라우드격차 reject (dev/cloud)
전체 (n=51)31/51 = 60.8%28/51 = 54.9% −5.9pp13 / 17
정직 서브셋 (n=18)8/18 = 44.4%8/18 = 44.4% ±0.0pp5 / 9
학습 포함분 (n=33, 참고)23/33 = 69.7%20/33 = 60.6% −9.1pp8 / 8
평균 지연0.1–0.3 s1.7 s
해석. 대분류 정답률만 보면 두 경로는 사실상 동률이다(정직 서브셋 ±0.0pp). 클라우드의 겉보기 열세(전체 −5.9pp)는 대부분 보수적 reject 정책에서 온다 — OOD 하드 게이트와 VLM이 저확신 케이스를 "기타/재촬영"으로 돌려보내는 건수가 더 많다(17 vs 13). 이는 오답을 정답처럼 확신 있게 표기하는 것보다 안내 품질 면에서 의도된 동작이지만, 단순 정답률 지표에서는 손해로 나타난다.
한계. ① 이 채점은 클라우드 전용 가치(탭 재분류, 빗금 실루엣, 증거 칩, OCR 텍스트가 있는 케이스의 부스트, 지역 조례 안내, 피드백 수집)를 포착하지 않는다 — 텍스트·마크가 있는 사진에서는 클라우드가 구조적으로 유리하다. ② n=18은 통계적으로 작다(±11pp 수준의 오차). ③ reject 를 "오답"으로 채점했다 — reject 후 재촬영 유도를 성공으로 보는 지표에서는 결론이 달라진다. 결론: 속도·오프라인은 온디바이스, 설명가능성·복합 장면·안내 품질은 클라우드 — 현행 기본값(클라우드 + 저확신 교차 폴백)이 타당하다.
