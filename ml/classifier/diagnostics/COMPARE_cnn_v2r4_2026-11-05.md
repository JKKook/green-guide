## 판정 의견 (GG_TRAIN)

- **과신의 원인은 label smoothing 차이로 확인됐다.** 바꾼 변수가 하나뿐이라서 그렇게 판단한다.
  - 틀린 장 평균 확신: 0.81 → 0.70 (v14 0.68)
  - 틀린 장 ≥0.95: 9 → 0 (v14 0)
  - 틀린 장 ≥0.8: 16 → 8 (v14 7)
  - VLM 발동: 8 → 17
  - 그 결과 two_stage가 39에서 43으로 올랐다.
- **그래도 가드에는 미달이다. 채택하지 않는다.**
  - 대분류 43/65 (기준 ≥44, 1장 부족)
  - 오탐 1/49 (기준 0)
  - 재현 11/16 (기준 ≥12)
  - CNN 단독 재현은 15/16이었는데, two_stage 단계에서 전자제품 4장을 잃었다. 원인은 VLM 중재나 reject 증가(3 → 7) 중 하나다. 장별로는 아직 확인하지 않았다.
  - v14와의 차이는 1~2장 수준이라 우열 근거가 되지 않는다(리더 규칙).
- **원인 정리 (r2 → r4 누적):**
  - 실사진 CNN 정확도 하락은 상태 헤드와 가중 샘플러 몫이다(r3에서 확인).
  - 과신과 VLM 구제 상실은 smoothing 0.0 몫이다(r4에서 확인).
  - 두 원인을 되돌리면 v2 분류 체계(세부 27)는 v14와 같은 수준이 된다. 같은 출처 test에서는 v14보다 조금 높다.
- **남은 차이 (미검증):**
  - VLM 발동이 17회로 v14의 25회보다 적다.
  - reject가 7로 v14의 12보다 적다.
  - two_stage에서 전자제품 재현이 15에서 11로 떨어졌다.
  - 이 장들을 장별로 보면 그 원인이 OOD τ 차이인지 VLM 프롬프트 쪽인지 갈린다. 아직 실행하지 않았고, gate를 다시 쓰지 않는 오프라인 분석으로만 가능하다.
- **다음 설계 제안 (실행하지 않음, 리더 판정 대상):**
  - 레시피를 고정한다: 재질 단독, smoothing 0.1, 셔플 샘플러. 상태는 별도 모델이나 VLM에 맡긴다.
  - 채택은 holdout 1회와 사용자 복귀 후에 판단한다(리더 지시 그대로).

- **VLM이 맞는 답을 뒤집은 장은 없다.** 놓친 5장 가운데 4장은 VLM이 아예 불리지 않았고, 1장은 VLM이 발동한 뒤 reject로 끝났다.
- **VLM 발동 문턱은 0.55다.** 서빙 코드의 `GREENGUIDE_API_VLM_TRIGGER_CONF` 기본값이다(`services/inference-api/src/routers/inference.py:275`, `core/config.py:155`). 0.8은 VLM 판정을 채택하는 문턱(`VLM_MIN_CONF`)이다. 앞선 비교 문서들에 적힌 'VLM 임계 0.8'은 채택 문턱을 가리킨다.
  - 놓친 4장은 확신이 0.67~0.91로 0.55보다 높아서 VLM이 발동하지 않았다.
- **1차 패스와 서빙 경로는 서로 다른 예측이다.** 1차 패스(재현 15/16)는 `realworld_serving_compare.py`가 오프라인 `realworld_gate.predict`(회전 TTA)로 계산한다. 서빙 two_stage는 API 경로로 추론한다. 놓친 4장은 1차 패스에서는 전자제품이었고 서빙 CNN에서는 다른 클래스였다.
  - 같은 현상이 v14에도 있다(1차 15/16 → two_stage 12/16). 그러므로 r4 고유의 결함이 아니라 두 경로의 차이다.
  - 경로 차이의 원인(TTA, 크롭, 전처리 중 무엇인지)은 미검증이다. gate를 다시 쓰지 않고 확인하려면 gate 밖 이미지로 두 경로를 대조해야 한다. 이 작업은 api 담당과 합의가 필요하다.
