# CNN 분류 체계 v2 — 3회차(v2r3, 절제) vs v14·v2r2 비교 (2026-11-05)

3회차는 **원인 확인용 절제**이고 채택 후보가 아니다. 2회차(v2r2)에서 두 가지만 바꿨다.
- 상태 손실 가중: 0.25 → **0** (`GREENGUIDE_HIER_V2_STATE_W=0`)
- 샘플러: 파손 가중 복원 추출 → **셔플** (`GREENGUIDE_HIER_V2_SAMPLER=shuffle`, v14와 같다)

나머지는 r2와 같다. manifest v22, 분할 v2.2(누설 0), resnet50, best 선정은 val 재질 손실 최소, label_smooth 0.0이다.
gate 65는 이 지시에서 1회만 썼다. holdout은 쓰지 않았다.

## 판정 의견 (GG_TRAIN) — 결과가 섞여 있다

- **CNN 단독 정확도는 v14 수준으로 돌아왔다.** 대분류가 28에서 33(argmax 기준 31에서 35)으로 올랐고, 재현도 11/16에서 15/16으로 돌아왔다.
  - 그러므로 r2의 실사진 정확도 하락은 **상태 헤드와 파손 가중 샘플러 몫**이다. 리더 판정 규칙의 "돌아오면 상태헤드/샘플러" 쪽에 해당한다.
  - 오탐은 8/49로 v14(15)보다 낮다. 다만 1~2장 차이는 채택 근거로 쓰지 않는다.
- **과신은 돌아오지 않았다.** 틀린 장 평균 확신이 0.81로 v14의 0.68보다 높고, ≥0.95인 틀린 장도 9장(v14는 0)이다.
  - 그래서 VLM 발동이 8회로 v14의 25회보다 적고, two_stage는 39/65로 기준 44에 못 미친다.
  - 그러므로 two_stage 격차의 원인은 상태 헤드가 아니라 **보정(calibration) 쪽**이다.
- **과신 원인 후보: label smoothing 차이 (레시피 차이는 확인됨, 인과는 미검증).**
  - v14는 `label_smooth=0.1`로 학습했다(`outputs/logs/v14_cycle.log`의 `backbone=resnet50, label_smooth=0.1`).
  - v2 세 회차는 모두 `GREENGUIDE_HIER_LABEL_SMOOTH=0.0`로 학습했다(run_v2*_train.sh).
  - smoothing 0.1은 정답 확률을 0.9 근처로 묶어 과신을 직접 낮춘다. 데이터나 세부 27 차이보다 먼저 확인할 가설이다.
- **다음 설계 제안 (실행하지 않음, 리더 판정 대상)**
  1. 재질 단독 헤드로 간다. 상태는 별도 모델이나 VLM에 맡긴다(리더 규칙 그대로).
  2. 그 회차는 v14 레시피에 맞춰 `label_smooth=0.1`로 학습한다. 과신 가설은 이 한 변수로 확인한다.
- **결함 기록:** `run_v2r3_train.sh`는 `train && export` 뒤 `rc=$?`를 찍는데, export가 실패해도 로그 끝이 `rc=0`이다. echo 안의 `$(date)`가 `$?`를 덮어쓰기 때문으로 보인다. 그래서 성공 여부는 `taxonomy.json` 존재로 확인했다. export 결함(STATE_W=0일 때 state gate가 None이 돼 크래시)은 `hier_v2.py`에서 고쳤고, 보정이 불가능하면 `min_confidence=1.01`로 둬서 상태를 출력하지 않게 했다.
